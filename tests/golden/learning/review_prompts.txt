3. Add a support file under such a skill with skill_manage write_file: references/<topic>.md for depth, templates/<name> for starter files to copy, scripts/<name> for steps worth running as a program. Add one line to its SKILL.md that points to the new file.

A preference about how one kind of job should be done belongs in that job's skill, not in memory; memory keeps only preferences that no skill owns.
If two skills overlap, say so in your reply; the curator merges skills later. Never delete or archive a skill in a review.

How to write a lesson into a skill:
- A skill is the way to do one class of job well for this user: the steps in order, the tools and commands that work, the shape the user wants the result in, and the traps that cost time.
- Put each lesson on the step it changes, as a rule in the imperative with one short reason ("Run the formatter before the type checker: the checker reads stale files otherwise.").
- Leave out the story of this session: no incident narration, no PR or issue numbers, no dates, no quotes of what the user said. The rule has to make sense on its own.
- One lesson, one rule. Before adding, look for the rule in the skill and its references/ files; sharpen the existing sentence instead of adding a second copy, and fix wrong text where it stands.
- Do not repeat what the project's instruction files or the tool descriptions already say.
- Do not record anything that only held on this machine or for a moment: a missing program, an unset key, a package not installed yet, a network blip, a flaky call that worked on retry. Never write that a tool "does not work". If setup was the problem, the fix (the install step, the setting) may go into a setup or troubleshooting skill.
- If nothing actually worked in this session, do not write the failed attempts up as a method.
- Rules that apply every time live in SKILL.md itself; references/ holds depth needed only sometimes, one file per topic (never per session or per incident).

Reply "Nothing worth keeping." only when the session was routine: no correction, no new technique, no skill that misled you. Otherwise make the change and reply with one line per change.
