How to read it: each row is one trust boundary — something crosses from a less trusted side to a
more trusted one. **Control** is what stops abuse; **Proof** names the tests that hold it (every
path is checked by `tests/security/test_threat_model_doc.py`; a `::name` must exist in that file);
**Status** is `held`, `fixed SEC-<n>` or `open SEC-<n>` (see Findings). The P25-02 suite
(`tests/security/`) re-pins each testable row at its product entry point; the deeper tests live
next to the code. The static guard `python -m tooling.checks security_static` keeps the risky code
shapes this review found out of `src/` and `scripts/` (row B-STATIC-1).

## Assets

| Id | Asset | Where it lives |
|---|---|---|
| A-KEYS | provider API keys, OAuth tokens, bot tokens, vendor app secrets | profile secret store (`secrets.json` 0600 or the OS keychain), `.env`, `auth.json` |
| A-HOST | the user's files and accounts on the host: SSH/cloud credentials, shell rc files, repositories | the user's home, any mounted path |
| A-EXEC | the ability to run commands as the user | terminal, background processes, code execution, hooks, quick commands |
| A-DATA | sessions, transcripts, memory, skills, cron jobs, board and room state | `state.db` and files under the profile home |
| A-CRED | session-scoped credentials: daemon WS tickets, dashboard session token / cookies, download tickets, API server keys, A2A peer tokens, relay and broker tickets | in memory, the daemon's control socket, the dashboard's state |
| A-VAULT | site logins kept for the browser tools | browser vault (encrypted with `INDUS_VAULT_KEY`) |
| A-SUPPLY | what the user installs and runs later: our release, its pinned binaries, plugins, hub skills, pm packages | installers, update, plugin/hub/pm stores |

## Actors

| Id | Actor | Can do |
|---|---|---|
| T-MODEL | model output (possibly steered by injected text) | call any offered tool with any arguments |
| T-INJECT | prompt-injected content: web pages, search results, MCP results, documents, repository files, A2A answers, emails, webhook payloads | put text in front of the model |
| T-STRANGER | a stranger on a messaging platform, an unauthenticated webhook or A2A caller | send events to listeners and adapters |
| T-NET | a network peer that reaches a listener (LAN, a public bind, a reverse proxy) | open TCP/HTTP/WS connections, rebind DNS names |
| T-WEB | a hostile web page in the user's own browser | make the browser send requests to loopback services |
| T-LOCAL | another local user on the same host | read world-readable files, `/proc/<pid>/cmdline`, connect to sockets it can reach |
| T-SUPPLY | plugin, MCP server, hub skill and package authors; a compromised mirror | ship code or text the user installs |
