## Goal
This phase is the roadmap's pressure valve (risk 3): everything here is P2/P3 and may slip to
post-1.0 with a D-id in `16-what-we-change.md` §2.8 rather than go silently missing. When it is done,
a single gateway process is able to host several profiles together with fail-closed scoping (P8 lifted, D-16.17);
several bots can deliberate in durable group rooms, also across machines through peer gateways; the
gateway can dial out to a relay connector and speak the A2A protocol; profiles can hand work to each
other on a task board with dispatcher-run workers; projects group folders, repos, sessions and a
board; edits get language-server diagnostics and a verify-on-stop gate; `indus import-agent` brings
over another coding agent's setup; the desktop app and the TUI get a pet and a wake word. The lead
also placed here every remaining unphased P2/P3 row: the `indus pm` helper-binary manager (S9); the
desktop's annotate/automation preview, capabilities and management pages, multiple connections
with SSH and native OAuth, bots, plugin SDK, themes, uninstall and voice (N12, N15–N17, N22, N25,
N28, N32, N34); the dashboard admin console and plugins (L15, L17); cloud and alternative browser
backends, the browser vault and private-URL routing (C22, C24, C25); the Docker egress proxy and
background memory caps (D15, D16); plugin packs (G7), extra hub sources and skill publishing (F27);
and suggested jobs and blueprints (H18); and the browser-control broker for external controllers (K39). Termux and MSIX channels are built only if capacity
remains (D-16.15).

## Interop note
Third-party protocols in this phase: A2A (Agent2Agent) protocol v1.0 (JSON-RPC over HTTP, agent card
at a well-known path, task states including input-required), the Language Server Protocol 3.17
(`initialize`, `textDocument/didOpen/didChange/didSave/didClose`, `textDocument/publishDiagnostics`,
`textDocument/diagnostic` pull, `shutdown`/`exit`, `ContentModified` error), the Debian package and
APT repository formats (Release/InRelease signing) for Termux, and the MSIX/App Installer manifest
schemas. Check each name against the vendor specification at the pinned version (A2A spec tag 1.0.x;
LSP 3.17; Debian policy current; MSIX schema for Windows 11 22H2+) and record the pin in the task
note; read the reference only for behaviour. Wake-word engines are dependencies, not protocols: pin
per D-16.52 (openWakeWord default; sherpa-onnx and Porcupine as optional extras, Porcupine only if its
licence passes the allow-list). Cloud browser providers (Browser Use, Browserbase, Firecrawl), password-manager CLIs (1Password `op`, Bitwarden `bw`), the ClawHub/LobeHub/browse.sh hub APIs and GitHub's REST API for skill publishing are vendor interfaces too: pin each API version in the task note and test against `respx` fakes. RFC 8252 (native-app OAuth with loopback redirect) and RFC 7636 (PKCE) govern P24-29. The relay connector contract is our own (D-16.1) and is documented
in `docs/user/relay-contract.md`.
