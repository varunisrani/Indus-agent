# P07 · CLI commands

**Weeks:** 12–13 (2 weeks) · **Track:** B · **Depends on:** P06 (click app, lazy groups, slash registry, chat); P01 (home/profiles, config load/save writer, `.env` io, `SecretStore`, logging); P02 (sessions, export/import, prune, integrity); P03 (provider profile registry, `/models` listing, context lengths); P05 (approval detector, child env, redaction) · **Status:** planned

## Goal
From a clean home, `indus setup` gets a person to a first answer in under three minutes (M2): pick
a provider, enter a key (stored in the OS keychain, P4), pick a model, choose the terminal backend
and tools. Every management command a daily user reaches for exists with the reference's shape
under our names: `model`, `fallback`, `auth`, `config`, `sessions`, `profile`, `tools`,
`approvals test`, `doctor`, `status`, `dump`, `logs`, `backup`/`import`, `checkpoints`,
`completion`. Every command behaves deterministically without a TTY (guidance + exit code, never a
hung prompt), which is an M2 acceptance criterion. No portal provider, no impersonating OAuth
(P2, P3); only documented device-code and PKCE flows.

Interop note: OAuth 2.0 Device Authorization Grant (RFC 8628: `device_code`, `user_code`,
`verification_uri[_complete]`, `interval`, `expires_in`, errors `authorization_pending`,
`slow_down`, `access_denied`, `expired_token`), PKCE (RFC 7636, `S256`), the refresh-token grant
(RFC 6749 §6) and OpenID Connect discovery are third-party standards: check field and error names
against the RFC texts, and each provider's endpoints against that provider's published docs at the
version recorded in the task note. The OpenAI-compatible `GET /v1/models` shape is checked against
P03's recorded captures. Read the reference only for edge cases.
