# P18 · Web dashboard

**Weeks:** 2.5 (plus frontend-track prework F3 from week 22, see "Prework") · **Track:** B+F · **Depends on:** P17 (daemon as shared backend: `SessionService` in the daemon, WS endpoint, single-use tickets, turn lease, control socket), P12 (the TUI renderer the chat tab embeds; `@indus/client`), P15 (gateway control, channels, pairing, webhooks), P14 (cron store), P13 (skills, plugins, MCP), P07 (sessions maintenance, profiles, doctor/backup operations), P01 (`SecretStore`, config writer), P00 (pnpm workspace, `@indus/ui`, Biome, vitest, Playwright) · **Status:** planned

## Goal

`indus dashboard` serves a React SPA and a FastAPI backend on `127.0.0.1:9119` that administer one
machine's Indus homes: sessions, config, keys, logs, analytics, cron, skills, plugins, MCP servers,
messaging channels, webhooks, pairing, profiles, models, files and system operations. The **Chat**
tab embeds the real TUI from P12 in xterm.js over a PTY WebSocket, so every TUI feature works in the
browser without a second chat implementation (R09.1). Off-host use fails closed unless a login
provider (username/password or OIDC, D-16.44) is configured (D-16.25). It proves the daemon (P17) can
be shared by a browser surface: the dashboard attaches to the profile daemon and starts it if needed.

**Prework (frontend track F3, weeks 22–30, mock data only).** Tasks P18-17 to P18-28 build the SPA
shell, the REST client, every page and the xterm host against `apps/web/src/testing/mockApi.ts`
(typed from the generated schema of the REST models in `indus.protocol`) and a fake PTY WebSocket
server. They need only P00 and the P18-17/P18-18 shell. Backend tasks P18-01 to P18-16 start when
P17 is green; F3 joins them in week 31 and swaps the mocks for the real server.
