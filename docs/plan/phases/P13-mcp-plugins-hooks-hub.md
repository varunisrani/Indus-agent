# P13 · MCP client, plugins, hooks and skills hub

**Weeks:** 2 · **Track:** B (backend, Python) · **Depends on:** P09 (skills format, resolver, index delta, memory stores, `on_skill_lifecycle` call sites), P05 (approvals, env builder, SSRF policy, redaction), P04 (tool registry and dispatch with the `ToolHooks` seam, prompt builder sections, `SessionService`), P01 (`SecretStore`, config writer) · **Status:** planned

## Goal
Indus gains tools and behaviour from outside its own code, safely. MCP servers configured by the
user connect over stdio or HTTP and their tools appear as `mcp__<server>__<tool>`, with a trust gate,
a breaker, OAuth and reload. Python plugins with a manifest load only when allowed and register tools,
hooks, commands, skills and providers through `register(ctx)`; a hooks bus with timeouts lets them
observe and steer the loop (a hung `pre_tool_call` blocks the tool). Plugins install from git with a
full SHA pin and a static scan; one external memory provider can run beside the built-in stores; the
skills hub finds, scans and installs skills and records where they came from; repo skills load only
after the user trusts the repo. This is the first half of milestone M4 ("an MCP server's tools appear
prefixed and callable; a plugin adds a tool and a hook").

Not in this phase (decided): curated plugin catalog and optional-MCP catalog (D-16.45), out-of-process
plugin host (D-16.46), plugin packs (G7, P3), hub sources ClawHub/LobeHub/browse.sh and skill publish
(F27, P3); gateway hook folders `HOOK.yaml` (G12) are P15-29; dashboard plugins (L17) are P18.

Interop note: MCP is a third-party protocol. Use the official MCP Python SDK at the version pinned in
`00-layout-and-conventions.md` §4 and check every method, notification and field name
(`initialize`, `tools/list`, `tools/call`, `notifications/tools/list_changed`, `resources/*`,
`prompts/*`, `sampling/createMessage`, `elicitation/create` form vs URL mode, `readOnlyHint`,
`structuredContent`, `_meta`, OAuth 2.1 + PKCE, Dynamic Client Registration, Client ID Metadata
Documents, RFC 8628 device code) against the MCP specification revision that SDK negotiates. The
agentskills.io `SKILL.md` standard, skills.sh, the `/.well-known/skills/index.json` convention, the
GitHub REST API (60 req/h anonymous, 5,000 with a token) and the OSV API are checked against their
published docs at the date in each task note. The reference is read for behaviour only.
