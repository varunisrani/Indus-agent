# P23 · Packaging and release

**Weeks:** 38–39 (2 weeks) · **Tracks:** B (installers, Docker, Nix, update, release tooling), F (desktop signing) · **Depends on:** P20 (desktop builds), P17 (gateway service restart), P07 (CLI app, `doctor`, backup snapshots) · **Status:** planned

## Goal
A person on a clean Linux or macOS machine runs one `curl … | bash` line, on Windows one
PowerShell line, or pulls a Docker image, or adds a Nix flake, and gets a working `indus` (or the
desktop app's runtime) without PyPI (P5, D-16.14). The installers never publish a half-cloned tree,
verify every bootstrap download by SHA-256, and record exactly one local outcome receipt (no
telemetry, D-16.49). `indus update` moves a source install between stable and canary channels
transactionally, rolls back a broken pull, and restarts this profile's gateway (D-16.57);
`indus uninstall` removes exactly what the installer added. A maintainer cuts a release with one
script: an attempt ref locks the version, CI tests the admitted commit, and only those tested bytes
are published to GitHub Releases and GHCR (D-16.58); aliases move last, from a receipt. Versions are
SemVer, canaries `x.y.z-canary.<UTC stamp>` (D-16.56). Desktop builds gain one signing path per OS.
Agents prepare and dry-run all of this; tagging, publishing and signing secrets stay with the owner
(skill reference 08 §1).

Interop note: these are third-party formats and tools; check names against their docs at the
pinned versions, not against the reference: uv CLI and `uv.lock` (version pinned in
`scripts/install/pins.json`), PEP 517/621/735, hatchling build hooks, Docker/BuildKit/buildx and OCI
image manifests, GHCR, s6-overlay (ISC; directory layout `/etc/s6-overlay/s6-rc.d`, `/init`),
hadolint rule ids, Nix flakes + flake-parts + uv2nix + pyproject.nix, NixOS and home-manager module
option types, electron-builder signing hooks, Apple `codesign`/`notarytool`/`stapler`, Windows
Authenticode `signtool` (or Azure Trusted Signing), GitHub Actions (`workflow_dispatch`, `needs`,
`concurrency`, OIDC) and the GitHub REST API for releases. Record each pinned version in
`docs/notes/P23/tool-versions.md`.
