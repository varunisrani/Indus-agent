# P03 · Providers and fake model

**Weeks:** 4–6 (1.5 weeks, runs beside P02 after P01) · **Track:** B (Python) · **Depends on:** P01 (`Scope`, config schema, `SecretStore`, env view, clock, errors, logging, redaction); P00 (fakes skeleton, D-04.1 harness) · **Status:** planned

## Goal
The runtime can talk to real model APIs and to a fake one through the same code: a registry of
declarative provider profiles (aggregator, Anthropic, OpenAI-compatible vendors, local servers,
named custom endpoints), exact host matching so a key only ever goes to its own host, route
resolution where saved config beats stale shell exports, an SSE parser, async Chat Completions and
Anthropic Messages transports that stream normalized events, stale-stream detection that scales
with context size, a partial-stream stub, an error classifier and Retry-After-aware backoff,
context-window resolution, and a scriptable fake model that speaks both wire formats over
`httpx.MockTransport`. Two recorded live captures per transport replay in CI (D-04.5). The phase
also finishes the D-04.1 asyncio trial so P04 can decide it. No turn loop yet: P04 drives these.

Interop note: Chat Completions (`messages`, `tools`, `tool_calls`, `tool_call_id`, `stream`,
`stream_options.include_usage`, `max_tokens`/`max_completion_tokens`, `reasoning_effort`,
`finish_reason` `stop|length|tool_calls|content_filter`) and Anthropic Messages (`system`, content
blocks `text`/`tool_use`/`tool_result`/`thinking`, `thinking.budget_tokens`, `anthropic-version`
header, SSE events `message_start`, `content_block_start`, `content_block_delta`
(`text_delta`, `input_json_delta`, `thinking_delta`, `signature_delta`), `content_block_stop`,
`message_delta`, `message_stop`, `ping`, `error`) are third-party protocols. Check every field
against the vendors' published API references as of the capture date (record the date and doc
URL in each capture's header); SSE framing against the WHATWG HTML "Server-sent events" section.
Read the reference's code only for behaviour and edge cases. No vendor LLM SDKs (D-04.5); no
header, prompt line or tool rename that claims another product's identity (R01.12, D-16.11).
