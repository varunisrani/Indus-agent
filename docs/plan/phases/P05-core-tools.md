# P05 · Core tools

**Weeks:** 9–10 (2 weeks) · **Track:** B · **Depends on:** P04 (registry, dispatch, toolsets, budget/spill, SessionService broker); P01 (`Scope`, config writer, `SecretStore`, base redaction filter, clock); P02 (session row fields for cwd and auto-approve) · **Status:** planned

## Goal
The agent can work on a real machine through the local backend: run foreground and background
shell commands with a hard timeout backstop, manage background processes, read, write and patch
files with the safety guards, search the tree, search and extract the web behind an SSRF policy,
keep a todo list and ask the user clarifying questions. Every flagged command passes the approval
pipeline (floors first, manual mode by default, D-16.53) through a server request answered on the
surface; no child process ever sees a provider key; secrets are masked in every output. The shared
execution contract and its contract-test suite are the base P11 and P21 extend to six more
backends.

Interop note: ripgrep (`rg`) command-line flags and JSON output, the V4A patch envelope
(`*** Begin Patch` … `*** End Patch`, as published with OpenAI's apply-patch tool) and the web
search vendors' HTTP APIs are third-party formats. Check each against the vendor's documentation
for the version pinned in `uv.lock` / the doctor's minimum `rg` version (14.x); read the
reference only for behaviour and edge cases.
