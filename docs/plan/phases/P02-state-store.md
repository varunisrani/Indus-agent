# P02 · State store

**Weeks:** 4–5 (1.5 weeks) · **Track:** B (Python) · **Depends on:** P01 (`Scope`, home/profiles, `fsio`, ids, errors, clock, logging, config `database.*`/`sessions.*`) · **Status:** done (Agent 2, wave 4)

## Goal
One SQLite store per profile at `<home>/state.db` that later phases can trust: a single writer with
time-budgeted retries, WAL that is never silently downgraded, bounded read-only connections,
schema 1 with declarative column reconcile, sessions and messages with stable ordering and durable
ids, compression continuations that never lose a concurrent append, unique titles, full-text
search that fails open, usage, JSONL export/import, delete with tombstones, prune and gated
VACUUM, read-only browsing, and plain-language error buckets. It ends milestone M0: the D-04.6
stress test passes and `indus doctor --minimal` shows home, profile, config sources, keychain
status and store health (`python -m indus.state.doctor_report`; the `indus doctor --minimal` spelling is wired by P07-19).

Interop note: SQLite and FTS5 names (`journal_mode`, `BEGIN IMMEDIATE`, `wal_checkpoint(PASSIVE)`,
`application_id`, `integrity_check`, FTS5 `content=`/`content_rowid=`, `unicode61`, `trigram`,
`'rebuild'`, `'merge'`, `bm25()`, `snippet()`) are third-party; check each against the SQLite
documentation for the SQLite version uv's Python 3.13/3.14 ships (record it in the P02-02 note;
`doctor` reports it). Read the reference's code only for behaviour and edge cases.

Not in P02 (owners): runtime input ledger and receipts (P15/P17), gateway routing slice and
Telegram topic tables (P15), lost-WAL capture, OFD lock guard and cross-process holder scans
(P17, B22), schema-surgery repair and salvage (`sessions repair/recover`, P07), in-place
compaction (P08, rotation only here), CJK bigram index (P2, later), startup watchdog (P15),
background coalescing usage writer (P08), per-session advisory lock `state/session_lock.py`
(P04-21, D-16.69).
