# P20 · Desktop app → Demo 4

**Weeks:** 3.5 (plus frontend-track prework F4 from week 22, see "Prework") · **Track:** F (+B) · **Depends on:** P17 (daemon as shared backend: `indus gateway ensure --json`, owner-only control socket, single-use WS tickets, event replay since cursor, server-request re-delivery, durable queue, admission receipts), P18 (headless `indus serve` REST API the desktop calls through main, and its `serve ensure`/`discover` command; git/fs/audio routes per D-16.68), P12 (`@indus/client` channel, buffer, heartbeat, backoff), P07 (`indus setup` provider flows, `doctor`), P00 (pnpm workspace, `@indus/ui`, Biome, vitest, Playwright) · **Status:** planned

## Goal

A desktop app on Electron (`apps/desktop`, product name "Indus") that installs or finds the Indus
runtime on a clean machine, attaches to the profile daemon, onboards a provider and chats with
streaming, tool rows, approvals, a session sidebar and working panes (preview, files, git review,
terminal). It is hardened beyond the reference (D-16.18–D-16.20): every IPC handler checks its
sender, every renderer page has a strict CSP, Electron fuses are set, and untrusted content can never
open a URL. One variant only (no remote-only "light" build, D-16.48) and no separate native setup
installer (D-16.47): first run goes through the in-app installer driven by the installer scripts'
stage protocol. Builds are **unsigned** on macOS, Windows and Linux; signing and notarisation are P23
(R08.22); the 1.0 Windows installer is signed NSIS (D-16.70) and MSIX is deferred (D-16.15). It proves the daemon (P17) and REST server (P18) serve a rich native client.

**Prework (frontend track F4, weeks 22–30, fake backend only).** P20-01 to P20-07 (main process,
bridge, security, windows, secrets) and P20-15 to P20-16 (renderer shell, boot overlay) build against
`apps/desktop/testing/fakeBackend/` — a small Node process that answers the ensure command, the
control-socket ticket mint, a WS JSON-RPC endpoint (via P12's `fakeServer`) and the REST routes the
app calls, with scripted delays and failures. Renderer chat tasks (P20-17 to P20-24) can run on the
same fake after P12. Everything else waits for P17/P18.
