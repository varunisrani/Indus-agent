# P15 · Gateway core + Telegram, Discord, Slack → Demo 3

**Weeks:** 2.5 (calendar weeks 25–27) · **Tracks:** backend (Python) · **Depends on:** P14 (cron grammar, job store, ticker, delivery targets), P13 (hooks bus, plugin registry), P10 (STT and vision tools), P05 (approvals, env builder, redaction), P04 (`SessionService` in-process host, server-request broker, slash registry), P02 (store) · P12 not needed · **Status:** planned

## Goal
One gateway process per profile (P8, D-16.17) runs in the foreground or as a user service and
connects Telegram, Discord and Slack at once. A person can chat with the same agent from all three,
run chat slash commands, approve a dangerous command with a button (a bare "yes" never approves),
send voice notes and images, and receive cron output in a chat. Final replies are recorded in a
durable delivery ledger before any send, so killing the gateway between "reply produced" and
"platform acknowledged" yields a labelled recovered reply after restart. The OpenAI-compatible API
server and the webhook receiver run in the same daemon. Every adapter is proved against a fake
platform through one shared contract suite that P16 reuses. The gateway runs agent turns through
the P04 `SessionService` in-process host; making the daemon the backend for every other surface is
P17.
