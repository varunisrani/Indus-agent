Edge cases / failure modes:
- a session key without `session_id` → `INVALID_PARAMS` (path `session_id`), as the bridge;
- a session this connection did not attach (another connection's) → `SESSION_NOT_FOUND`;
- bad values (`busy=fast`, `yolo="yes"`, `fast=warp`, empty reasoning / model) → `INVALID_PARAMS`
  with the bridge's message;
- `/yolo` while an unattended (`-z`) turn holds the session's auto-approve: the person's choice wins
  and the turn's end does not switch it back off (the host forgets its own switch);
- a model switch while a turn runs → `deferred` (the session's mutation, applied at the next turn);
  a model in `tui.confirm_models` or one whose window cannot hold the context → `CONFIRM_REQUIRED`
  until `confirm: true`;
- `/status` reads the queued count off the loop (a store read), 0 when nothing waits.

Our design differences / decisions:
- one module for the writes (`service.config_writes`) so both transports validate alike; the bridge
  keeps its per-view parts (pending model, its own tool-progress mode, its projector);
- the daemon's model switch goes through `session.mutate`'s `model` operation (the session's gate,
  its row, deferred at the turn boundary), not a direct binding change;
- `verbose` with a session is this connection's own mode for it (the bridge's mode is one viewer's
  too); not saved, read back by `config.get` on the same connection. The daemon still sends every
  tool event (no per-viewer projection yet): follow-up.

## Decisions for the lead
- W50-a-1 (D-16.1150): one module for `config.set`'s checks and profile writes (`service.config_writes`); the
  bridge's `methods_config` delegates to it (no change there: its contract tests pass untouched)
  and keeps what is per view (the pending model, its viewer's tool-progress mode, its projector).
- W50-a-2 (D-16.1151): `verbose` with a session on the daemon is this connection's own mode for that session
  (`Subscriptions.set_tool_mode`), read back by `config.get` on the same connection, dropped when
  it lets the session go; not saved. `session.info.tool_progress` stays the profile's (W48-h-6).
  The daemon does not yet hide or trim tool events by that mode (the bridge's `off` / `new`
  filter and argument / result caps): follow-up (a per-viewer projection in `Subscriptions`).
- W50-a-3 (D-16.1152): the daemon's model switch over `config.set` is `session.mutate`'s `model` operation: a
  deferred pick applies when the next turn starts (`before_turn`), where the bridge applies it as
  soon as the running turn ends; the mutation's context-window check also answers
  `CONFIRM_REQUIRED` (with its message) besides `tui.confirm_models`; a refusal answers
  `PROVIDER_UNAVAILABLE` with the mutation's message.
- W50-a-4 (D-16.1153): `yolo`, `fast`, `reasoning` change the shared session for every viewer; each applied
  switch puts a `session.info` into the session's events (all its viewers), as the bridge sends
  its one viewer. `reasoning` is applied under the session's mutation gate.
- W50-a-5 (D-16.1154): a person's `/yolo` while an unattended (`-z`) turn holds the run-scoped auto-approve
  wins: the host forgets its own switch for that session, so the turn's end no longer turns it
  off (`DaemonSessionHost.set_auto_approve`). The row is written off the loop before the switch;
  a session with no row yet (before its first reply, D-16.426) keeps the switch live only, as in
  `--local`.
- W50-a-6 (D-16.1155): `/yolo`, `/reasoning`, `/fast` are shared server commands now
  (`slash_commands.HANDLERS`, through the new `SlashHost.set_switch`); `DAEMON_REFUSED` keeps
  `/queue` only and the daemon's catalogue lists the three as `server`. `SlashHost.queued` is
  async; the daemon's `/status` counts the inputs waiting in the session's durable queue (every
  viewer's, the running one excluded), where the bridge counts its viewer's own queue.
- W50-a-7 (D-16.1156): no protocol change was needed: `config.set` was already declared (catalogue, generated
  TS types, field docs); `codegen --check` and both twins' `--check` unchanged. Slice [b]'s
  protocol additions do not meet this slice.
