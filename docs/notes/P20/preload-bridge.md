What it does (own words): the renderer reaches main only through `window.indusDesktop`, an object
the preload builds with `contextBridge.exposeInMainWorld`. The preload is plain JavaScript (bundled
from TypeScript into one CommonJS file, because a sandboxed preload cannot run TypeScript or
require anything but `electron`). The object is generated from the channel table: for each channel
the table names a group and a method, and the preload adds a thin wrapper —
`invoke` channels become `(payload) => Promise<answer>`, `send` channels `(payload) => void`,
`event` channels `(listener) => unsubscribe` with the listener called with the payload only (the
Electron event object is never handed over), and `sync` channels become static launch facts read
once at load. No wrapper returns or exposes `ipcRenderer`, an event, a sender or a port. Answers
come back as the registry's envelope; the preload returns the value or throws an `Error` whose
message starts with the code (`sender-rejected: …`). The REST proxy's expected 404 is a value
(`{ kind: "not-found", status: 404, body }`), never an exception.

`src/global.d.ts` is generated by `scripts/gen-bridge-types.mjs` from the same table and the zod
schemas (JSON Schema → TypeScript), and a test regenerates it in memory and fails when the
committed file differs, so the renderer and main cannot drift.

Inputs → outputs:
- channel table + schemas → `window.indusDesktop: IndusDesktopBridge` (`facts`, `boot`,
  `connection`, `api`, `profile`, `windows`, `zoom`, `external`, `fs`, `git`, `terminal`,
  `preview`, `updates`, `notifications`, `deepLinks`, `logs`, `secrets`, `journal`, `work`).
- `node scripts/gen-bridge-types.mjs [--check]` → writes `src/global.d.ts` (or exits 1 when stale).

Files: `apps/desktop/electron/preload.ts`, `apps/desktop/electron/preload.test.ts`,
`apps/desktop/electron/ipc/bridge.ts` (the pure builder the preload and the test share),
`apps/desktop/src/global.d.ts` (generated), `apps/desktop/scripts/gen-bridge-types.mjs`,
`apps/desktop/scripts/gen-bridge-types.test.ts`.

Edge cases / failure modes:
- a listener that throws → caught and logged in the renderer console, other listeners still run;
- unsubscribe called twice → no-op;
- facts channel refused or missing → `facts` holds safe defaults (`windowKind: "main"`, no custom
  controls), the bridge still loads;
- an envelope that is not an envelope (main bug) → `internal: malformed answer`.

Our design differences / decisions:
- The bridge object is built from the table instead of written by hand (one source of truth; the
  reference's hand-written object has ~259 entries).
- Errors carry a code prefix; expected 404 is a typed value.
- Groups dropped for 1.0 (see the Compare checklist): vendor billing, free tier, cloud (D-16.12);
  later: pet, wake, bots, plugin SDK, HUD modifier gestures (P24).

Tests we will write:
- exposed object: walk it, call every function with a fake `ipcRenderer`; nothing returned or
  reachable is `ipcRenderer`; only declared methods exist; facts are plain data.
- listener receives the payload only (one argument, not the event); unsubscribe removes it.
- invoke unwraps the envelope; error envelope → `Error("code: message")`; not-found value passes.
- typings regenerated equal the committed file (stale check).

## Contract for P20-08+

The renderer codes against `window.indusDesktop` (type `IndusDesktopBridge`, `src/global.d.ts`,
generated); main codes against `registry.handle / on / sync / emit` with payloads typed from
`electron/ipc/schemas.ts`. Both come from one table, `electron/ipc/channels.ts` (76 channels at P20-07; 111 after P20-39, table below).

Rules every slice follows:
- Add or change a channel = one row in `channels.ts` (name `indus:<group>:<action>`, kind, bridge
  group + method, owner task) + one entry in `schemas.ts` (strict request object; `response` /
  `payload` shape) + `node scripts/gen-bridge-types.mjs`. The stale-check test fails otherwise.
- Register handlers only through the registry, inside one `install…(context: MainContext)` step
  added to the INSTALL STEPS list in `electron/main.ts`; `scripts/check-ipc.mjs` fails on anything
  else. Handlers get the parsed payload and `{ senderId }` (a checked, known window's
  `webContents.id`); throw `IpcError(code, message)` for an expected failure.
- Answers reach the renderer as values; failures reject with `Error("<code>: <message>")`
  (`sender-rejected`, `bad-request`, `not-available` until the owner lands, `internal`, or the
  handler's own code). The REST proxy's 404 is the value `{ kind: "not-found", status: 404, body }`.
- Events: main pushes with `registry.emit(webContents, name, payload)` (payload checked against
  its schema); renderer listens with `indusDesktop.<group>.<onX>(listener)` → unsubscribe; the
  listener gets the payload only.
- Credentials never cross the bridge except the single-use WS ticket from `connection.ticket`
  (P20-10): no serve session token, no remote token, no provider key.
- `MainContext` (`electron/context.ts`) carries: registry, windows (WindowManager: `isKnownWebContents`,
  `describe`, `raise(win, reason)`, `openSecondary/openInstance`, zoom), log (`write(text, level)`,
  `recent()`), paths, appOrigin, csp (`addConnectOrigin` for daemon/serve origins), dev/packaged/
  platform/appVersion/deepLinkScheme, machinery (`guard` every spawn/reap/claim — R08.3),
  activation + externalOpener, secrets (`DesktopSecrets`), shellPath (await before spawning).
